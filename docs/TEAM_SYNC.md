# Командная часть (FTB Teams)

Работает, только если Пергамент стоит на сервере и установлен FTB Teams. Без этого мод полностью автономен.
Учитываются только party-команды FTB (личная «команда из одного» — не команда).

## Что видно и чем делимся
- **Сокомандники на карте** — где бы они ни были, но только над разведанным в показываемом измерении.
  Сервер раз в 0,5 с шлёт каждому игроку с модом позиции онлайн-сокомандников (с модом или без).
  Кто в прорисовке, рисуется как обычный игрок, без дубля.
- **Открытая карта** — у сокомандников с модом. При первом входе в команду на сервере клиент отдаёт свой архив,
  дальше — свежие сканы. Принятое сливается в свою карту навсегда.
- **Руды** — события подтверждённых находок (индикатор, руками, проспектор) с id: каждое вливается ровно раз.
- **Не передаются**: метки, рисунки, тропы, шахтёр, мобы, метки гибели.

## Карта команды на сервере
`world/pergament/teams/<UUID команды>/` — регионы в том же формате, что у клиента, индекс `index.pgti`
(чанк → `seq`, класс, автор; «воплощение» карты) и `finds.json`.

- Класс записи: **LIVE** (свежий скан) заменяет чанк, **ARCHIVE** (архив, импорт) только заполняет пустое.
- `seq` растёт на каждую принятую запись команды. Запись синхронизации — всегда полный чанк 16×16.
- Регионы пишутся на диск раньше индекса; при потере индекса начинается новое «воплощение» — клиенты
  начинают с нуля и отдают архив заново.

## Протокол (канал `pergament:team`, необязателен с обеих сторон)
| Пакет | Направление | Смысл |
|---|---|---|
| `Hello` | клиент → сервер | у меня есть мод |
| `Mates` | сервер → клиент | позиции онлайн-сокомандников |
| `TeamInfo` | сервер → клиент | твоя party (или её нет) |
| `SyncFrom` | клиент → сервер | у меня всё до `watermark` этого воплощения — дошли остальное |
| `Upload` / `FindUp` | клиент → сервер | свои чанки (LIVE/ARCHIVE) / находки, с номером для подтверждения |
| `Push` / `FindPush` | сервер → клиент | чанки / находки команды: свежие или докачкой |
| `Mark` | сервер → клиент | после записи карты команды на диск: всё до `seq` у тебя есть, выгрузки до `ack` легли |

- Докачка при входе отдаёт всё новее `watermark`, сгруппировав по регионам; `watermark` клиент запоминает
  только по `Mark` и только после того, как принятое легло в его регионы. Повторная доставка безвредна.
- Докачка не перезаписывает чанки, которые в этой сессии клиент сам сканировал или получил свежими.
- Архив засчитывается по подтверждению сервера (`ack`): обрыв связи не теряет и не задваивает данные.

## Защита сервера
Всё, что прислал клиент, проверяется: автор — из соединения, команда — из FTB на сервере, измерение — из реестра;
потолки на размер пакета (24 КиБ от клиента), распаковку (ровно один чанк), темп (256 чанков/с с игрока),
очередь задач, квоты команды (1,5 млн чанков, 200 тыс. находок). Диск и сжатие — на отдельном потоке.

## Проверка
- Юнит-тесты: кодек чанка, хранилище команды (LIVE/ARCHIVE, выдача по `seq`, рестарт, битый индекс), находки.
- Живой самотест двумя клиентами: `bash tools/teamtest.sh` — dev-сервер с FTB Teams, клиенты Alice и Bob,
  party собирается командами FTB; проверяются позиции, архив, свежие сканы, находки и отметки.
